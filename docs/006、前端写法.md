# 前端写法

适用于 `atelier-ui`。写页面、加路由、写图表时看这一篇。

## 表格页直接写，不用通用封装

- 表格页用 Element Plus 的表格加分页组件直接写，数据、加载状态、分页参数在页面里自己管。
- 为什么不用带缓存、防抖、多种刷新策略的通用封装：学起来比直接写还费劲，实际项目里也没人用它。模板的写法要和实际项目一致，才有参考价值。
- 每个表格页会有一些重复代码，这是接受的代价，换来每个页面都能按需自由改。
- 坑：快速切换搜索条件或翻页时，先发的请求可能后返回，把新结果覆盖掉。要丢弃过期的响应。

## 路由写在代码里，不从后端下发

- 路由一律在代码里配置，组件用 `() => import(...)` 引用，不支持从接口拉菜单、按字符串加载组件。
- 为什么：页面本来就是代码，要先写出来才能访问，由后端下发路由并没有带来真正的灵活性。按字符串加载组件，路径写错要到运行时才发现；写成 import，构建时就会报错。
- 页面能不能看见，靠路由上声明的权限码控制，见《会话与权限》。

## 图表交给 vue-echarts

- 图表的初始化、尺寸自适应、销毁都交给 vue-echarts，不自己管理图表实例的生命周期。图表配置写成 computed，数据或主题变了自动更新。
- 每个图表组件自己按模块注册用到的图表类型和组件，不在全局一次注册全部。用一个图表，就只打包这一个。
- 坑：漏注册某个组件（比如图例、提示框）时，图表照样画得出来，只是缺了那一块，控制台会有报错。

## 路径别名只留 `@`

- 为什么不多加别名：每个别名都要在 `tsconfig` 和 Vite 配置两处同步，漏一处的话类型检查不报错，构建却失败。
- 引用全局的东西（公共组件、store、工具函数）用 `@/`。只在一块内部共享的，比如几个页面共用、还没稳定到能做成全局组件的模块，用相对路径。路径本身就说明了依赖范围。

## 枚举写成 `as const` 对象

- 不用 TS 的 `enum`，写成 `as const` 对象，再从它推出取值的类型。
- 为什么：`enum` 不是纯类型语法，要编译器额外生成代码，一些只擦除类型的工具不支持它；数字枚举还会生成反向映射，遍历时容易多出一倍的键。
- 取值和后端的枚举名保持一致，见《后端约定》。

## 界面文案走 i18n

- 界面上的文案都放进语言包。人手写时可以只写中文，缺的英文会回退成中文显示；AI 写时顺手把英文补上。
- 后端返回的数据（用户姓名、权限名等）不归前端翻译，控制台日志也不必。
- 坑：在 setup 里一次性生成的文案（表单校验规则、搜索栏配置等）要写成 computed，否则切换语言后不会跟着变。
