# 后端约定

适用于 `atelier-engine`。建表、写接口、改认证或缓存时看这一篇。接口的响应格式见《接口约定》。

## 枚举存枚举名

- 一般情况下，库里和 JSON 里都存 Java 枚举的名字（`ENABLED`、`MALE`）。Jackson 与 MapStruct 默认就按名字转换，不用额外写转换代码。
- 行业专有名词往往很难翻成准确的英文。这类取值可以在库里存中文，代码里仍用英文命名的枚举，两者之间做映射。
- 为什么不存数字：库里看不懂，枚举顺序一调整，数据就全错了。
- 为什么不用 PostgreSQL 原生 ENUM：取值很难删改。用 `VARCHAR` 加 CHECK 约束一样能限定取值，改起来只是换一条约束。
- 坑：
  - 加枚举值时，要同时写迁移脚本更新 CHECK 约束，否则新值写不进库。
  - 枚举常量改名等于改数据，要连库里的存量一起迁移。

## 不区分大小写的唯一性用 `LOWER()` 唯一索引

- 比如用户名、邮箱：建 `LOWER(col)` 上的唯一索引兜底，接口层再先查重，给出具体的提示文案。
- 为什么不用 CITEXT：它是扩展，要额外安装和启用。
- 坑：查询时也要写 `LOWER(col) = LOWER(?)`，否则用不上这个索引，查重结果也和索引的判断对不上。

## 长度不好定的字符串用 `TEXT`

- PostgreSQL 的 `TEXT` 不用定长度，和 `VARCHAR(n)` 相比也没有性能损失。长度说不准的，就先不定。
- 比如密码哈希：不用 `CHAR(60)` 这种按 BCrypt 写死的长度，长度由算法决定，以后才换得了算法。
- 坑：从 MySQL 转过来的人习惯给每个字符串定长度，在 PostgreSQL 里没有必要。

## 基础数据不进 Flyway

- Flyway 只管表结构。权限点、超级管理员这类基础数据由应用启动时准备。
- 权限点写在一个配置文件里，每次启动同步进库：新的插入，改过的更新，文件里删掉的置为禁用。
- 为什么删掉的不真删：库里还有角色分配引用着它；而且权限码一旦发布就不该被重新使用。
- 超级管理员只在用户表为空时创建一次。之后再改初始密码的配置，不影响已有的密码。
- 坑：权限码发布后不改名。改名等于删掉旧的、新增一个，所有角色都得重新分配。

## jOOQ 生成的代码提交进仓库

- 生成代码要起临时数据库跑迁移。把生成结果提交进仓库，普通构建就不依赖 Docker。
- 坑：改完迁移脚本要重新生成并一起提交，否则代码和表结构对不上。

## 超级管理员只在两处特判

- 它拥有全部启用的权限，不走角色；它不能被删除或禁用。除此之外和普通用户一样。
- 计算「某人有哪些权限」的逻辑只放在一处，别在各处各自判断是不是超级管理员。

## 权限码缓存在 Redis

- 用户的可用权限码缓存起来，设一个较短的过期时间兜底。
- 改了用户的角色或状态，清这个用户的缓存；改了角色的权限、角色的状态，或者同步了权限点，清全部缓存。
- 坑：清缓存要等事务提交之后再做。提交前清掉的话，并发的请求可能把旧数据又读回缓存。

## 认证拦截器不查库

- 认证拦截器只管认证：会话里有没有用户 id。它不查库确认用户仍存在且启用，省掉每个请求一次查询。
- 用户被删除或禁用的情况由授权兜住：业务接口检查权限时，被删除或禁用的用户算出来的权限是空的，调什么都会被拒绝。
- 拦截器先于路由匹配，所以未登录访问不存在的路径，得到的是 401 而不是 404。这是有意的，不暴露有哪些路径。

## 不做级联删除

- 还有关联数据时拒绝删除，返回 409，让用户先手动解除绑定再删。比如角色还分配给用户时，不能删这个角色。
- 一来实现简单，二来避免误删：级联删除会悄悄带走关联数据，比如用户的权限无声无息地变少。

## 集成测试共用一套环境

- 所有集成测试共用一个 Spring 上下文和一套容器，跑一次只起一次数据库和 Redis。
- 坑：别在单个测试里加会改变上下文的注解（比如 mock 掉某个 Bean），否则会多起一套上下文和容器，测试变慢很多。
- 测试镜像固定到小版本，不用 `latest`，也不只固定大版本。只固定大版本的标签照样会被悄悄更新，代码一行没动，测试就挂了。
  - 实例：`timescale/timescaledb-ha:pg16-oss` 有一次更新后，镜像不再自动在库里装好 TimescaleDB 扩展，要自己 `CREATE EXTENSION`；而且 `-oss` 镜像里没有 TSL 模块，启动时却仍默认去加载它，不加 `-c timescaledb.license=apache` 就建不了扩展。
  - 固定小版本的标签形如 `pg16.14-ts2.29.2`，PostgreSQL 与扩展的版本都写死。小版本尽量和生产对齐。
